# 완전 로컬 문서 맞춤법 검사기 구현 계획

## 1) 요구사항 확정 및 의존성 정리
- 현재 초안의 `requirements.txt`는 `import` 구문과 패키지명이 혼재되어 있어, 설치 가능한 패키지 목록으로 정리합니다.
- 내장 라이브러리(`zipfile`, `xml.etree.ElementTree`, `re`, `difflib`)는 `requirements.txt`에 넣지 않습니다.
- 완전 로컬 기준으로 기본 의존성을 다음처럼 확정합니다.
  - `chainlit`
  - `pymupdf` (PDF 추출)
  - `python-docx` (DOCX 추출)
  - `kss` (한글 문장 분리)
  - `nltk` (영문 문장 분리)
  - `language-tool-python` (영문 맞춤법/문법/구두점, 로컬 Java 서버)
  - `kiwipiepy` (한글 토큰화/형태소 보조)

## 2) 파일별 텍스트 추출 계층 구현
- 포맷별 extractor를 분리해 동일한 출력 스키마를 반환합니다: `[{page:int, text:str}]`.
- **확장자 기반 if-else 라우팅을 명시적으로 구현**합니다.
  - `if ext == ".hwpx"`: 파이썬 내장 라이브러리(`zipfile`, `xml.etree.ElementTree`, `re`) 기반 파싱
  - `elif ext == ".pdf"`: `pymupdf`(=`fitz`) 기반 파싱
  - `elif ext == ".docx"`: `python-docx` 기반 파싱
  - `else`: 지원하지 않는 포맷 오류 반환
- `pdf`:
  - PyMuPDF의 페이지 단위 텍스트 추출을 사용해 페이지 번호를 정확히 매핑합니다.
- `docx`:
  - 문단 단위 추출 후 “가상 페이지” 전략을 사용합니다.
  - 기본값: N자(예: 1800~2200자) 또는 문단 수 기준으로 page index를 부여.
- `hwpx`:
  - ZIP(XML) 구조를 파싱해 문단 텍스트를 복원하고, `docx`와 동일한 가상 페이지 전략 적용.
- 파일 위치

## 3) 문장 분할 및 문맥 인덱싱
- 페이지 텍스트를 문장 배열로 분할하고, 오류 리포트 시 앞/현재/뒤 문장을 제공하도록 인덱싱합니다.
- **문장별 언어 판별 후 if-else 분기**를 수행합니다.
  - 한글 비율 우세 문장: 한국어 파이프라인으로 분기
  - 영문 알파벳 비율 우세 문장: 영어 파이프라인으로 분기
  - 혼합 문장: 기본은 한글 파이프라인 우선, 필요 시 두 파이프라인 순차 검사
- 한글 분리: `kss.split_sentences`
- 영어 분리: `nltk.sent_tokenize`
- 각 문장에 `doc_id`, `page`, `sent_idx`를 부여해 추적 가능하게 합니다.
- 파일 위치
  - [C:\Users\user\Desktop\local\01spelling_checker\src\nlp\sentence_splitter.py](C:\Users\user\Desktop\local\01spelling_checker\src\nlp\sentence_splitter.py)

## 4) 검사 엔진(한글/영어) 설계
- 영어 검사:
  - `language-tool-python` 로컬 서버 모드로 문장별 검사.
  - 반환값에서 오류 유형(맞춤법/문법/구두점), 제안 후보, 오프셋을 수집.
- 한글 검사(완전 로컬 현실적 대안):
  - `kss + 정규식 + (선택) pykospacing` 조합을 기본 설계로 반영.
  - 형태소 보조(`kiwipiepy`)는 규칙 정확도 보강 용도로 함께 사용.
  - 1차 규칙: 띄어쓰기 이상 패턴, 반복 구두점, 괄호/인용부호 불균형, 조사/어미 인접 공백 이상치 등.
  - 2차(선택): 사용자 사전 기반 오탈자 패턴 매칭(`difflib` 유사도 활용).
- **검사 분기 로직(문장 단위)**:
  - `if detected_lang == "ko"` -> 한국어 검사기(`kss+regex(+pykospacing)`)
  - `elif detected_lang == "en"` -> 영어 검사기(`nltk+LanguageTool`)
  - `else` -> 혼합/미확정 정책에 따라 병렬 또는 순차 검사
- 결과 스키마 통일:
  - `{"lang","category","message","suggestions","page","sentence","prev_sentence","next_sentence","span"}`

## 5) Chainlit 앱 통합

- 업로드 → 확장자 if-else extractor 선택 → 문장 분할/언어판별 if-else → 검사 실행 → 결과 표시 파이프라인 구현.
- UI 출력은 다음 순서로 정렬:
  - `페이지` → `언어` → `오류유형` → `문제 문장` → `앞/뒤 문장` → `수정 제안`
- 대용량 문서 대응을 위해 페이지/문장 단위 배치 처리와 진행 메시지 추가.

## 참고: 현재 requirements 초안에서 수정할 점
- `requirements.txt`에는 `import ...` 줄을 넣지 않습니다.
